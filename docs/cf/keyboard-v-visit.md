# Keyboard V visit arm

V is the keyboard twin of the tray Visit button: it runs exactly
the button's verb, toggling visitArm and refreshing the tray, so
the key and the button can never disagree. The Visit button is
disabled with no selection, so V needs a selection too: arming a
resident-targeted verb with no subject would leave the gold armed
treatment standing over nobody, and the next resident tap would
eat the visit instead of selecting. V is the button's own initial,
claimed by no other key, so no mnemonic compromise is needed; it
is the first resident-targeted armed verb to gain a key, because
Model's initial M is already the Sound mute key.

V carries the button's whole verb, not just its toggle: it clears
the button's own armed-verb clear list (the generic arm flag,
Model, Proclaim, Speak, Cover, Groups) and toasts on arming with
the tap-who wording naming the selected resident ("Tap who X
should visit: they walk over for a chat"). It deliberately does
not clear the state the button leaves alone: Found, Claim, and
Road keep the button's own grammar, so the key mirrors the button
instead of inventing a wider clear. The Visit button's title names
it ("Visit (V key)"), so a desktop player can learn V exists from
the button itself.

V is guarded like a panel key, not like the display-only pause and
mute keys: it fires only once the game has started, never while
the game is over, never while an incident panel stands, never with
Ctrl, Meta, or Alt held, never while typing in a text field, and
never with no selection. An armed verb over a modal decision would
hide the decision it needs, so the incident guard is intentional,
not an omission. Do not add an incident exception here without
re-arguing that panel rule: the guard is intentionally identical
to the camera, group, idle, lens, story, thoughts, claim,
proclaim, found, and road keys, not to Space, P, 0, or M.
